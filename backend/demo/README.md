# 시연(전시)용 데이터

전시·발표에서 앱을 보여주기 위한 준비 자료예요.

- **구장은 공공데이터의 실제 풋살장을 넣어요.** 국민체육진흥공단 "전국체육시설 정보"에서 정상운영 중인 풋살장만 골라 이름·주소·위치·실내외를 그대로 넣어요.
  - 이 구장들은 아직 F-Mate 제휴 구장이 아니에요. **코트·시간표·가격은 시연용 예시**이고, 구장 설명에 "실제로 예약되지 않아요"라고 적혀 나와요.
  - 그래도 앱에서는 **실제 구장 이름으로 날짜·시간 선택 → 토스 테스트 결제 → 예약 확정 → 취소·환불**까지 전부 동작해요(테스트 결제라 돈은 안 나가요).
- **SNS(영상·게시물)는 팀원이 직접 만들어요.** 실제 계정으로 앱에서 영상을 올리면 업로드·인코딩·재생까지 실제로 동작하는 걸 보여줄 수 있어요.

> **먼저 정할 것: 서버를 어디서 돌릴지.**
> 구장·팀 계정·영상은 **그 서버의 DB와 저장소에 저장**돼요. 지금 PC 서버에 넣었다가 클라우드로 옮기면 다시 넣어야 해요.

## 1. 실제 풋살장 넣기 (공공데이터)

**준비:** 공공데이터포털에서 "국민체육진흥공단_전국체육시설 정보" 활용신청 → 승인되면 마이페이지에 **일반 인증키**가 보여요.

`C:\dev\fmate` 에서 PowerShell로 (서버가 켜져 있어야 해요):

```
docker run --rm -e DATA_GO_KR_KEY="여기에인증키" -v "C:\dev\fmate\backend\demo:/work" python:3.12-slim python -u /work/import_public_futsal.py
```

- 전국 체육시설 15만여 곳을 훑어서 풋살장만 고르느라 **몇 분** 걸려요. 진행 상황이 표시돼요.
- 끝나면 `완료: ... public_futsal.sql 를 만들었어요`와 지역별 개수가 나와요.
- 특정 지역만 넣으려면 `-e REGIONS="서울특별시,경기도"` 를 추가해요 (시도 이름 그대로).

만들어진 파일을 DB에 넣어요:

```
docker compose cp backend/demo/public_futsal.sql db:/tmp/public_futsal.sql
docker compose exec db psql -U fmate -d fmate -f /tmp/public_futsal.sql
```

`COMMIT` 이 나오면 끝이에요. 앱의 예약 탭·풋살장 탭을 당겨서 새로고침하면 실제 풋살장이 보여요.

- **사진·편의시설:** 공공데이터에는 사진·시설 정보가 없어서, 앱이 사진 대신 **코트 일러스트**를 보여주고 편의시설은 **시연용 예시**로 채워요(구장 상세에 그렇게 표시돼요). 편의시설만 다시 채우려면 `public_futsal_facilities.sql` 을 같은 방식으로 실행해요.
- 시간표는 우선 14일치가 생기고, 서버가 켜져 있으면 매일 새벽 30일치까지 자동으로 채워요.
- 다시 실행하면 이전에 넣은 공공데이터 구장(과 그 구장의 시연 예약·결제)은 지워지고 새로 들어가요.
- 공공데이터 구장만 지우기: `public_futsal_reset.sql` (아래 4번과 같은 방식으로 실행)
- 화면 어딘가에 **"정보 출처: 국민체육진흥공단 전국체육시설 정보(공공데이터포털)"**를 밝혀 두세요 (공공누리 출처 표시).

### 운영자·관리자 계정 (선택)

```
docker compose cp backend/demo/demo_seed.sql db:/tmp/demo_seed.sql
docker compose exec db psql -U fmate -d fmate -f /tmp/demo_seed.sql
```

`owner@fmate.demo` (구장 운영자), `admin@fmate.demo` (관리자), 비밀번호 모두 `demo1234`.

## 2. 팀 계정 만들고 영상 올리기 (앱에서 직접)

팀원 3~4명이 각자 계정을 만들어요.

1. 앱 → **회원가입** (이메일, 비밀번호, 닉네임, 약관 동의)
2. 프로필 설정 (소개, 지역, 포지션). 프로필 사진도 올릴 수 있어요
3. **이메일 인증** — 영상을 올리려면 필요해요. 인증 코드는:
   - PC 서버: http://localhost:8025 (Mailpit)에서 확인
   - 클라우드 서버: 메일 발송을 설정했으면 실제 메일함으로 와요
4. **영상 올리기** — 홈 상단 **＋** → 영상, 또는 숏폼 화면의 업로드
   - **90초 이하**, 500MB 이하, mp4 또는 mov
   - **세로 영상**이 숏폼 화면에서 가장 보기 좋아요
   - 올린 뒤 1~2분 지나면 "처리 중"에서 재생 가능 상태로 바뀌어요 (서버가 스트리밍용으로 변환)
5. 사진 게시물, 해시태그(`#풋살` 등), 구장 태그도 섞으면 피드가 풍성해 보여요
6. 팀 계정끼리 서로 **팔로우**, 좋아요, 댓글을 몇 개 남겨 두세요

**에뮬레이터에서 영상 올리기:** 영상 파일을 에뮬레이터 화면에 **끌어다 놓으면(drag & drop)** 에뮬레이터의 다운로드 폴더에 들어가요. 그다음 앱에서 영상을 고를 때 그 파일을 선택하면 돼요. 실제 휴대폰이 있으면 갤러리에서 바로 고르면 되니 더 편해요.

**사용할 영상:** 팀원이 직접 찍은 영상만 쓰세요. 인터넷에서 받은 경기 영상이나 음악이 들어간 영상은 저작권 문제가 생길 수 있어요.

## 3. 시연 순서 (3~5분)

1. **새 계정 가입** — 관람객 앞에서 그 자리에서 가입 (이메일 인증 없이도 둘러보기·팔로우·좋아요 가능)
2. **추천 피드 / 숏폼** — 팀이 올린 영상이 바로 보여요. 세로 스와이프로 넘기기
3. **팔로우** — 팀원 프로필 → 팔로우 → 홈의 "팔로잉" 피드에 그 사람 게시물만 모여 보임
4. **좋아요** — 영상에 좋아요 → 팀원 계정에 알림이 감 (두 번째 휴대폰으로 보여주면 효과적)
5. **예약 탭** — 날짜 → 지역 → 시간대 → **실제 풋살장 목록** → 구장 상세(설명에 "시연용 시간표" 안내) → 연속 2시간 선택 → 합계 금액
6. **내 주변 실제 풋살장** (카카오 REST 키를 넣은 경우) — 풋살장 탭 → "내 주변 실제 풋살장 보기" → 사설 풋살장까지 포함한 카카오 검색 결과 → **예약 체험** (같은 구장이 공공데이터에 있으면 그 구장, 없으면 가까운 구장으로 연결)
7. **결제** (토스 테스트 키를 넣은 경우) — 예약하기 → 토스 결제창 → 예약 확정 → 내 예약 → 취소 → 환불
   - 예약은 이메일 인증이 필요하니, **결제 시연은 미리 인증해 둔 팀 계정으로** 하는 게 안전해요
8. **채팅** — 팀원에게 메시지 → 두 번째 휴대폰에서 실시간 수신
9. **운영자 화면** (선택) — `owner@fmate.demo`로 로그인 → 마이 → "구장 운영자 입점 안내" → 입점 신청 → `admin@fmate.demo`로 승인하는 흐름

시연에서 새로 만든 계정은 전시가 끝난 뒤 관리자 화면에서 정리하거나 그대로 둬도 돼요.

## 4. 지우기

| 무엇을 | 파일 |
|---|---|
| 공공데이터 구장 + 그 구장의 시연 예약·결제 | `public_futsal_reset.sql` |
| 시연 계정(`@fmate.demo`) | `demo_reset.sql` |

```
docker compose cp backend/demo/public_futsal_reset.sql db:/tmp/r.sql
docker compose exec db psql -U fmate -d fmate -f /tmp/r.sql
```

- **팀원이 만든 계정과 영상·게시물은 지우지 않아요.**
- 전시 전날 공공데이터 구장을 한 번 다시 넣으면(1번 다시 실행), 시연 중 테스트로 잡은 예약이 사라져 깨끗하게 시작할 수 있어요.

## 주의

- `@fmate.demo` 계정 비밀번호는 공개된 값(`demo1234`)이니, 실제 서비스 서버에는 이 데이터를 넣지 마세요.
- 관리자 계정으로 승인·제재 같은 작업을 하면 그 기록(감사 로그)은 설계상 지울 수 없어서, 지우기를 해도 관리자 계정은 남아요. 다시 넣기를 하면 남은 계정을 그대로 써요.
