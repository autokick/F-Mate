# 04. 진행 현황 (2026-10-10 기준, 최종 패키지)

## 먼저 읽을 것 — 검증 범위

이 저장소를 만든 작업 환경은 **Maven Central·pub.dev·Flutter SDK 다운로드가 막혀 있어서** Spring Boot 서버와 Flutter 앱을 **컴파일·실행하지 못했다**.
그래서 아래 표의 "검증" 열을 정직하게 나눠 적었다.

| 검증 수준 | 의미 |
|---|---|
| **실행 검증** | 실제 PostgreSQL 16에서 테스트를 돌려 통과를 확인함 |
| **정적 검증** | 서버 SQL 338개 문장을 실제 스키마에 PREPARE 해 통과, Java 전체 구문 검사 통과, 앱↔서버 API 경로·필드 대조 불일치 0건 |
| **미검증** | 코드는 작성했지만 컴파일·실행은 사용자 PC에서 처음 하게 됨 |

서버 통합 테스트 27개(JUnit + Testcontainers)와 앱 테스트 20개(flutter test)는 **작성만 했고 실행하지 않았다**. 첫 빌드에서 컴파일 오류가 날 수 있으며, 오류 메시지를 붙여 주면 고친다.

분류: **완료**(구현 + 실행 검증) · **구현됨(미검증)**(코드 완성, 로컬 빌드·실행으로 확인 필요) · **부분 구현** · **미구현** · **외부 승인 필요**

## 개발 중 발견해 고친 문제 (주요)

1. 부분 겹침 동시 예약 시 교착상태 → 코트 단위 잠금 (C2)
2. 동시 요청으로 사용자 선점 3건 제한 우회 가능 → 사용자 단위 잠금 (C7)
3. 확정된 예약에 결제 레코드 추가 가능 → 트리거에서 예약 상태 검사
4. 운영시간 겹침이 "이미 예약됨" 오류로 보이던 문제 → 서버에서 먼저 검증
5. 메일 미설정 시 헬스체크 DOWN으로 배포가 막히던 문제 → 기본 off
6. 숏폼 업로드 재시도 시 같은 멱등키 재사용 → 시도마다 새 키
7. 스토리지 키가 없으면 구장 입점(서류 첨부)이 불가능해 로컬에서 예약 흐름을 시험할 수 없던 문제 → docker compose에 로컬 S3 호환 저장소 추가 (MinIO 이미지가 Docker Hub에서 삭제된 뒤 SeaweedFS로 교체)
8. 로그아웃해도 푸시 토큰이 남아 다른 사람 알림이 올 수 있던 문제 → 로그아웃 시 토큰 해제

## 다음에 할 일 (권장 순서)

1. **사용자 PC에서 첫 빌드**: `docker compose up -d --build` → `flutter test` → 실행. 오류는 그대로 붙여 주면 수정
2. 토스페이먼츠 **테스트 키**(가입 즉시 무료) 입력 → 예약·결제·취소·환불 전 과정 실제 확인
3. 실제 기기에서 카드사 앱 호출, 사진·영상 업로드 확인
4. Firebase·Google Maps 키 → 푸시·지도
5. 소셜 로그인 앱 SDK 연동 (카카오 → 구글 → 애플)
6. 법률 검토(약관·정산 구조), 사업자 절차 → 라이브 결제 → 스토어 출시
